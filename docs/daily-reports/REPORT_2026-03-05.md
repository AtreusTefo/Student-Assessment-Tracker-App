## ✅ What Was Completed

### 1. Delete Button Fixed (Student List)
The Delete button clicked but nothing happened — no modal, no error, no response. Traced to three stacked bugs:
- `showConfirmDialog = true` was set inside `ngZone.run()` but Angular never re-rendered the `*ngIf` modal. Fixed by adding `cdr.detectChanges()` after setting the flag.
- `confirmDelete()` and `cancelDelete()` also lacked `cdr.detectChanges()`, so the modal could fail to close. Fixed.
- `loadStudents()` was being called twice on init (leftover duplicate). Removed.

### 2. Form Inputs Disabled During Submission (Student Form)
All 9 input fields on Create/Edit Student remained editable while the API request was in flight, allowing mid-submit data changes. Added `[disabled]="loading"` to every input. Locked the Cancel anchor too using `[routerLink]="loading ? null : '/'"`  and a `.disabled` CSS class.

### 3. Server-Side Field Errors Now Clear on Keystroke (Student Form)
After a server validation error (e.g., duplicate ID/Passport No.), the inline field error persisted indefinitely — even after the user corrected the value. Added a `clearFieldError(field)` method and wired `(input)="clearFieldError('fieldName')"` to all 9 inputs. The top-level error banner also auto-clears when all field errors are resolved.

### 4. Full Route Protection Implemented
All pages were accessible without authentication. Implemented a complete auth guard system:
- **`AuthGuard`** (`core/guards/auth.guard.ts`) — redirects unauthenticated users to `/login`
- **`GuestGuard`** (`core/guards/guest.guard.ts`) — redirects authenticated users away from `/login` and `/register`
- Applied both guards to all routes in `app.routes.ts`
- Persisted auth state to `localStorage` in `TeacherStateService` so page refresh no longer logs users out
- Fixed post-registration redirect from `/login` to `/` (registration auto-authenticates, so `/login` caused a double-redirect via `guestGuard`)

## ⚠️ Challenges Faced

### Challenge 1: Silent Delete Failure Was Deceptive
The delete button produced absolutely no output — no console error, no network request, nothing. This made it hard to know where in the chain the failure was happening. The actual cause turned out to be a rendering problem (`*ngIf` not flushing), not a logic or API problem. The key insight was that `ngZone.run()` re-enters the zone for async tasks but does **not** force a synchronous view flush — `cdr.detectChanges()` is required separately for that.

### Challenge 2: Three Bugs Masking One Symptom
The delete issue was caused by three independent bugs simultaneously. Fixing just one (e.g., `showDeleteConfirm`) would have made the modal appear but left the dismiss broken. Understanding that all three needed to be fixed together required tracing the full lifecycle: click → modal open → confirm/cancel → close.

### Challenge 3: Auth Guard + localStorage Interaction with Registration Flow
After implementing the `guestGuard` on `/login`, the registration flow broke. Registration calls `setCurrentTeacher()` (which sets `isAuthenticated = true`), then navigated to `/login` — but the guard immediately redirected away. The fix was straightforward (navigate to `/` instead), but the root cause required understanding the interaction between the new guard, the state service, and the post-registration navigation sequence.

### Challenge 4: In-Memory Auth State on Page Refresh
The `BehaviorSubject` holding auth state resets to `null` on every page load. This meant that after adding the `authGuard`, refreshing any protected page would log the user out. Solving this required initialising the `BehaviorSubject` with a value restored from `localStorage` at service construction time — not just hydrating it after construction.
